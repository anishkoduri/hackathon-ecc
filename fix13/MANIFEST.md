## 2. Posture — CORRECTED (Anish, Nov 11, after the first posture draft)

The first posture draft ("maximalist-within-taste", "pick the bolder end", "bold is never a defect") was written into staged orchestrate + the assembler and then **RETRACTED in full before any build completed** — no bold-framed text ever reached a completed build. Anish: "Not necessarily bolder, just more. It said the search only returned a marketing website, I don't want it based off smth I want it unique so each design decision is routed thru the skills so it's amazing."

- **Posture is MORE, not bolder.** More design decisions made deliberately through the skills, more of the package applied, more craft. Boldness is neither the goal nor a defect; uniqueness and craft are the goal.
- **Anti-derivative rule (the core defect).** The live Home Run agent said "the design search only returned a marketing website" and based the design on it. New rule: **NO design may be based off a searched external reference** — not a marketing website, not a Dribbble shot, not a template, not any found page. Web search may inform FACTS (real product details, competitor awareness) but the DESIGN DIRECTION must be generated through the package skills: Hallmark theme deal (50-theme catalog), ui-ux-pro-max styles/palettes/font pairings/UX guidelines, design-taste-frontend page system (one system, one section per screen, hero + dealt moments), less-flat-ui treatments, motion skills, design-system tokens as applicable. The direction is recorded in `docs/design-tokens.md` (or the decision record for small changes) with its SOURCE named as the skill that generated it — never a URL, never "based on [found site]". (Does not change the adjudicated rule that explicit `--domain` plain search serves reference rows only — that is about search results as data, not about basing a design on a found page.)
- **Every design decision routed through the skills.** Theme, palette, typography, spacing, motion, component styling, state styling, responsive behavior — made BY a named package skill, not by the implementer's taste and not by copying a reference. The implementer brief names the deciding skill per decision; the record shows which skill decided what; Verify checks the record exists and matches what was built.
- **Distinctiveness bar — corrected.** FAILS generic or DERIVATIVE output: a design based on a searched reference, or a default template with no generated direction. It does NOT require boldness and does NOT fail boldness. The bar is: a unique direction, generated through the skills, recorded, and visibly applied. Guardrails unchanged (Impeccable detector + craft floor + Harmony rule govern readability, contrast, alignment, consistency).
- Direction lenses (bolder, quieter, colorize, decolorize, delight, overdrive) STAY OUT (decided Nov 10) — the posture lives in how the existing package is applied, not in new lens commands.
