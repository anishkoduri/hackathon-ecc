## Flow walked (Campus Eats — campus food-ordering app for Texas A&M students)

First build, orchestrate-driven (orchestrate IS the first-build engine):
1. Step 0 narration-key prompt — sanctioned once, never blocks; KEY-RECEIPT recorded, key held in working context only.
2. Step 1 Scope (`hackathon-scope`) — Campus Eats scope: landing, menu browse, dish detail, cart, checkout, order tracking, student dashboard.
3. Step 2 Expansion Phases 0–3 (`feature-expansion`) — planner-approved list (e.g. live order tracking, dietary filters), no user gate.
4. Step 3 Slice — landing slice (Taste + dealt Hallmark theme) + app slices (menu browse, cart/checkout, orders dashboard, components); design package named in every UI brief; two-pass briefing so UI briefs restate real tokens from `docs/design-tokens.md`.
5. Step 4 Build — first wave: landing/design slice (Taste, Grok 4.7 High design-lead) writes `docs/design-tokens.md`; app slices via `ui-ux-pro-max` (Grok design-lead); scaffold via `app-scaffold`; expansion slices built per the Phase 4 brief format (UI rule names the full package).
6. Step 5a Verify — blind reviewer (record check only, never the screens); `browser-qa` visual loop on every primary route (landing, menu, dish, cart, checkout, tracking, dashboard; desktop + mobile); Hallmark step 6 (sloplint, 6-axis gates critique, finish review).
7. Step 5b Final polish (`polish-pass`) — fix-only; Harmony consistency check; template evidence appended to `.hallmark/candidate-evidence.md`; polish-routed redesign → design skill rebuilds → fresh `browser-qa` verdict run (up to 2 verdict rounds, redesigned screens only, at most 1 fix round per problem list, separate budget).
8. Step 5c Deploy (`deploy-fast`) — named re-verification check before deploy; hold if not re-verified. Step 5d `/demo` (`pitch-deck-video`) — films the LOCAL app only. Step 6 Commit + README + final report (+ six deferred end-of-project checks by name).
9. Standalone engine also walked: `orch-build-mvp` steps 1–9 (GAN loop per slice, `--skip-planner`), step 6 verify, 6b polish + fresh run, step 7 commit hold, step 8 deploy hold + demo, step 9 report.
10. GAN loop walked both ways: standalone `/gan-build` (planner path and `--skip-planner`) and `/gan-design`; rubric validation on every path; evaluator never scores screen distinctiveness.
11. One-prompt change walked: `orch-add-feature` "add dietary filter chips to menu browse" — design package in brief, direction recorded, `browser-qa` visual loop on the rebuilt surface via orch-pipeline Review.
12. One-prompt redesign walked: `orch-change-feature` landing redesign via the Hallmark redesign flow (`redesign.md`, `sloplint --before/--kept`), hero review re-run, `browser-qa` visual loop on the rebuilt surface.
13. One-prompt removal walked: `orch-change-feature` "remove the leaderboard" — feature-to-files inventory, delete + migration rule, grep reference check (cap 2 passes), tests, commit (auto-approved), redeploy, `shots.json` update, `/demo --rebuild` (local film).
14. `/demo` path walked: narration-key prompt once (never re-prompted in-run), SSML `<break>` scoped to the v2 family only, montage/explainer opt-in only.

  - `skills/orchestrate/SKILL.md:62` (5d): "`/demo` films the LOCAL app from the project dir only (`APP_DIR` to the app dir) — it never films a deployed URL; do NOT set `shots.json` `app.url` to the deployed URL. Deploy still happens first, but the video is made from the local app."

  - `skills/orch-build-mvp/SKILL.md:56` (step 8): "then film the LOCAL app from the project dir (`APP_DIR` to the app dir) — `/demo` never films the deployed URL, so do NOT set `shots.json` `app.url` to it. ### B3 — cold-start `/gan-build` generates the design direction on a non-Grok model, with no design-lead step before it
- Flow step: standalone `/gan-build` planner path (Campus Eats brief, no prior design step, no `docs/design-tokens.md` yet).
- Files:
  - `commands/gan-build.md:24`: "Launch the `gan-planner` agent as a Cursor subagent with the user's brief, plus the design direction recorded by the design-lead (model `grok-4.7-high`) in `docs/design-tokens.md` — the direction comes from the design-lead BEFORE the loop; the planner records it in the spec and the loop executes under it, it does not generate or re-derive a direction on its own"
