## Findings

### 83-A1 — MINOR: `commands/gan-design.md:17` carries the verbatim twin of the gan-build step-0 dispatch with no inline pin and zero `_F29` tokens

**Evidence.** `commands/gan-design.md:17` (Setup step 0, cold start): "…if neither the record nor the tokens file carries a direction (cold start — no direction recorded yet), dispatch to the design skill for that surface — `design-taste-frontend` for a landing page, `ui-ux-pro-max` for a dashboard/app surface — on model `grok-4.7-high`, first to generate the direction through the package skills (per the design-package rule) and record it in `docs/design-tokens.md`, then restate that recorded direction in the brief/spec and proceed." Compare `commands/gan-build.md:26`, identical through "record it in `docs/design-tokens.md`" except for the trailing clause — and gan-build's line now carries the 82-A1 parenthetical while gan-design's does not. The file carries **0 `_F29` tokens** and **0 "Factory routing" lines** (grep-verified). MANIFEST §2(b) records the step-0 scoping decision for `gan-build.md` only; `gan-design.md` is not named in the record at all. Audit #80-A row 25 claimed `gan-design.md` has "No launch/subagent lines" — that claim is false for step 0: "dispatch to the design skill" is a dispatch line, and it escaped all three prior rounds because `dispatch` is not in the base-pattern grep set.

**Why it matters.** Same hazard as 82-A1, same shape: if a reader executes step 0 as a spawned subagent — the natural reading of "dispatch … on model X" — that spawn writes `docs/design-tokens.md` with no director brief, no NO-GUESSING rule, and no verification step, and its dashboard-path target (`ui-ux-pro-max`) carries no factory routing at all. The 82-A1 pin exists precisely to rule that reading out, but a reader of `/gan-design` never sees it: the file has no pointer to inherit the pin from, and the MANIFEST record does not name this site. Minor, not blocking: the orchestrator-role reading is the better one for the same reasons as in 82-A1 (design-lead is the orchestrator's own model and role per `orchestrate:31`; direction generation is a big decision governed by DESIGNPKG-AUTO; cold-start only); and the loop this step feeds is covered by reference — the Loop section states "Same as `/gan-build` Phase 2", whose pointer (`gan-build.md:12`) governs the generator/evaluator passes — so the gap is confined to the step-0 design dispatch, not the build loop.

**Fix.** Apply the 82-A1 option (a) to the second site: add the identical parenthetical to `gan-design.md:17` ("(the design-lead is invoked inline as the orchestrator here, not spawned as a drone — a spawned execution must carry a director brief)") and extend the MANIFEST §2(b) record to name `gan-design.md:17` as the second step-0 site under the same reading and revisit trigger. (Alternatively, if the coordinator holds that `/gan-design` is a legacy/experimental path, record that explicitly with the reason — but the step-0 text is live instruction either way, so silence is not a third option.)

### 83-A2 — MINOR: `agents/ecc-gan-planner.md:44` instructs the planner drone to invoke the design-lead and write `docs/design-tokens.md` — unrecorded, and the 82-A1 inline reading cannot apply to it

**Evidence.** `agents/ecc-gan-planner.md:44` (Direction source): "…the design-lead step in `/gan-build` Phase 1 records the direction before this agent launches — if this agent is ever launched with no direction recorded, invoke the design-lead (model `grok-4.7-high`) to generate it through the package skills and record it in `docs/design-tokens.md` first, then copy it here — never a searched external reference, per the anti-derivative rule". Pre-existing: the identical line is present at `:44` in the fix28-base copy (`fix29/scratch-repo/.../ecc-gan-planner.md`), so this is not a fix #29 regression — it is a coverage gap in the routing-set determination, missed by all three prior rounds because `invoke` is not in any dispatch-verb grep set used. MANIFEST §2(b) does not name this site; the 82-A1 record pins only `gan-build.md:26`.

**Why it matters.** This is the one design-direction site where the 82-A1 justification does not transfer: the invoker here is the planner, itself a drone — a drone cannot invoke the design-lead "inline as the orchestrator", because the planner is not the orchestrator. As written, the fallback instructs a drone to cause a direction generation plus a project-file write with no director brief, no NO-GUESSING rule, and no verification step, and no text anywhere pins its execution form. Minor, not blocking: the fallback is defensive and unreachable on the normal path — the same sentence states the gan-build step records the direction "before this agent launches", and `gan-build.md:26` step 0 always runs first, so the condition ("ever launched with no direction recorded") fires only on a direct planner launch bypassing `/gan-build`; and the work itself is the same orchestrator-level design-direction generation already scoped in 82-A1, on a single small record file.

**Fix.** Either (a) record the site in MANIFEST §2(b) and re-route the fallback: the planner stops and reports the missing direction to the orchestrator (a NEEDS_CONTEXT-style return naming what is missing) instead of invoking the design-lead itself — the orchestrator then invokes the design-lead inline per the 82-A1 reading — or (b) pin the execution form in the role-file line itself (orchestrator invokes the design-lead inline; a spawned execution must carry a director brief). Option (a) is the cleaner one, since a drone cannot execute the inline reading and the orchestrator is the only actor that can.
