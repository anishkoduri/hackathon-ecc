## New findings

### 84-B1 — MINOR (verifier) — check 7d asserts only 2 of the 7 DIRECTOR-BRIEF fields per template, and only 4 of 9 items in the feature-expansion format

**Evidence.**

- `verify29.py:731–832` (check 7d(b)): for each of the six brief-shaped sections in `dispatch-prompt.md` (skeleton, recon, mechanical, reasoning, blind reviewer, worked example) it asserts only `"Verification steps" in _sec` and `"files out of scope" in _sec`. The other five fields — Goal, Inputs (files in scope), Constraints, Acceptance check, Return format — are asserted nowhere per template; they appear only in the contract-core check (7d(a)), which reads a different block.
- Demonstrated false-pass (i): deleting the `Acceptance check: every claim carries a path:line anchor` line from the recon template alone in a scratch copy leaves verify29 at **261/261** — a template that has lost its acceptance criterion passes the "brief-completeness" check.
- Demonstrated false-pass (ii), same family: 7d(c) asserts only feature-expansion format items 2 (out of scope), 4a/4b (acceptance/verification split), and 9 (return format). Deleting the Constraints label from item 3 (`3. Constraints: global rules that bind this feature` → `3. (constraints removed)`) in a scratch copy leaves verify29 at **261/261** — a format that has lost its constraints item passes.
- The live tree is currently correct: my independent field scan of every dispatch-prompt section confirms all six brief-shaped sections carry all seven fields as distinct slots (Goal, Inputs = exact paths, Constraints + files out of scope, Acceptance check, Verification steps, Return format), and the feature-expansion format carries items 1–9 intact. So this is latent only.

**Why it matters.** 7d exists because audit #80-B10 proved a naming check is not a completeness check, and #81-A1/B6 proved a bare count cannot distinguish "four occurrences in the right places" from "one template missing and another doubled". The per-template fix repeated the same shape one level down: it checks the two fields that were missing in round 2, not the seven the SPEC requires. A later edit that drops a Goal, Acceptance check, or Return-format line from one template — or a Constraints item from the feature-expansion format — would pass verify29 while shipping briefs a drone cannot execute without guessing. Same consequence class as 83-B1, one step wider.

**Fix.** Extend 7d(b) to assert all seven field labels per section (e.g. `Goal:`, `Inputs:`, `Constraints:`, `Acceptance check:`, `Verification steps:`, `files out of scope`, `Return format:` — the labels the templates actually use), and extend 7d(c) to assert format items 1 (goal/fit) and 3 (constraints) alongside 2/4a/4b/9. Verifier-only change; no tree change needed.

### 84-B2 — MINOR (verifier) — check 9b's DeepSeek/Qwen name grep is scoped to SKILL.md + *.mdc, so a model reference in a references/ or commands/ file passes

**Evidence.**

**Why it matters.** 9b's stated property is "DeepSeek/Qwen names occur only in the GLOBAL-ROUTING block" — a fix-#30 guard: no model assignment may land before fix #30. A fix-#30-style name could land in exactly the file that dispatches work and verify29 would stay green.
