> `- After fixes, run a **second blind deep-reasoner pass** over the fixed diff to re-verify (the second-pass pattern replaces any second-model peer review).`

- The fix cycle sends code changes to two named agents: mechanical fixes to fast-worker, architectural fixes to deep-reasoner. Both roles write/change project files. This is implementation dispatch under the §2(a) scope rule.
- The file carries **0 `_F29` tokens** (verified by grep); no verify29 check mentions `astra-review` except the KEPT_COMMANDS list (`verify29.py:261`); no routed skill invokes this command; no factory pointer, no director brief, no no-guessing bound, no correction-brief path for the fix dispatch.
- **Why every prior round missed it:** all prior triage cites only step 2, `:24` ("Dispatch a blind review to the deep-reasoner as a fresh subagent" — review-only, correctly out of scope). The string "fix cycle" occurs **0×** in audit80–89 reports and in MANIFEST.md. Step 3 contains no base-pattern verb (`spawn`/`dispatch`/`subagent`/`delegate`/`implementer`) and no verb from any prior round's wider sweeps — "Fixes go to X" is a role-routing sentence, a new escape class in the same family as 83-A1 ("dispatch" not in the grep set) and 86-A1 ("invokes" not in the grep set).
- **Why the subagent reading holds (not inline role-adoption):** (a) step 2 in the same command establishes the execution model — deep-reasoner runs as a **fresh subagent** with a pinned model; (b) the command intro frames the whole run as three passes in that model ("a blind deep-reasoner pass for the review, fast-worker for fixes, deep-reasoner again for re-verification"); (c) fast-worker and deep-reasoner are defined subagent roles (`agents/fast-worker.md:9`, `agents/deep-reasoner.md:9`: "The orchestrator delegates … work to you"); (d) the named pins (`cursor-grok-4.6-high-fast`, `grok-4.7-high`) are subagent-tier pins. The second blind pass at `:33` is itself a subagent dispatch (review-only, out of scope — the finding is the fix dispatch at `:32`, not the re-verify pass).

Narrower than react-build pre-87-B1 in one respect: a verification loop already exists (the second blind pass + repeat-until-zero-blockers), so no new verify step is needed — but the pointer must still name the brief's acceptance criteria as what the second pass checks (see the 87-B1 lesson below).

**Concrete fix (react-build precedent, fix29.py §5h + verify29 + MANIFEST §2(b) record):**
1. Add a one-line factory pointer immediately after the `:32` fix-cycle line, mirroring `react-build.md:9`: the fast-worker/deep-reasoner fix runs as a single-task factory drone with a director brief (goal, files in/out of scope, constraints, acceptance criteria, verification steps, what to return), no-guessing, and orchestrator verification against the brief's acceptance criteria. Either extend `:33` to name the brief's acceptance criteria as the check, or keep the pointer to the brief + no-guessing + a correction-brief re-dispatch path and let the coordinator adjudicate the wiring.
